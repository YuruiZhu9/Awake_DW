## 变更内容

- **撤回窗口**：成笔后 `UNDO_WINDOW_MS = 10_000`；`HomeUiState` 增 `undoAvailable` / `undoAmountMl`，窗口只活在 ViewModel（旋转保留、进程死亡丢失，不新增持久化键）。
- **落点**：主按钮胶囊尾端原本的「+{cupMl}ml」在窗口内换成「1dp 发丝分隔 + 撤回」；不新增纸带、气泡或第四条文字通道，胶囊高度不变、主文案不位移。
- **撤回行为**：一击调用 `undoLatestCup()`（同步收窗后删今日最后一笔，不弹确认）；环心回执「已撤回 · {n}ml」；同时收起猫语气泡与达标横幅、猫心情落回当前时段、旧防抖窗作废（同刻可补记）；庆祝标记不回滚。窗口只消费一次——快速双击不会删到再上一杯。
- **无障碍**：尾端独立语义节点、`role = Button`、48dp 可点高、`contentDescription = "撤回上一杯，{n}ml"`；单击完成。撤回无音效，只一次 CLOCK_TICK 轻触觉。
- **动效**：尾端 Crossfade 240ms；减少动态时长归零。

## 实现期决策

1. **为什么放在按钮里**：环下纸带与达标横幅同分区，达标杯恰好最需要撤回，会叠成两条纸带；长按是隐藏手势；统计页行内撤回与「历史记录需确认」的纪律冲突。按钮尾端与「记一杯」同源、零布局跳动、不新增表面，是唯一同时满足三通道纪律与 48dp 的落点。
2. **为什么 10s**：环心引文停留 3s，读完正文与落款后仍有余量反悔；同时短于「去统计页确认删除」的路径，纠错成本与记录成本相当。窗口到期直接退回杯量，不做倒计时装饰。
3. **为什么撤回不弹确认**：NN/g 确认弹窗研究——确认只留给高风险、不可逆、低频操作，「不要为日常动作使用确认弹窗」「尽最大努力提供 undo」。刚按下的一杯是即时误触，不是历史记录；统计页删除仍保留确认。
4. **为什么撤回要收回猫语/横幅**：那一杯已不存在，猫的回应与达标反馈失去依据；三通道必须同时收场，否则屏幕在庆祝一件被撤销的事。
5. **为什么作废旧防抖窗**：撤回是明确纠错；若保留旧窗口，同刻补记会被「刚刚记过了」挡住，等于惩罚纠错者。
6. **通知动作不纳入窗口**：通知侧记录不经过首页 ViewModel；纠错仍走统计页确认删除，如实披露。
