# Awake_DW · 个人定制喝水应用 设计文档

- 日期：2026-08-27
- 状态：已实施完结（2026-08-31 终审收口——§1–§12 全部落地并随 v0.1.1 归档；v0.2 艺术方向另见 moodboard 与开发计划）
- 技术路线：Android 原生 · Kotlin + Jetpack Compose

## 1. 产品概述

### 1.1 一句话定位

Awake_DW 是一个随一天的时间温柔变换颜色、每一次记录都被治愈的喝水应用。它以「我」的第一人称视角面向所有使用者——不管是谁装在手机上，都是「我」在自己的手机上使用它。

### 1.2 背景

- 很多人都经常忘记喝水。现有商店产品要么臃肿带广告，要么毫无个性。
- App 里融入**贴心的小考虑**：可编辑的文案库、随作息流转的主题色、有理有据的健康提示。
- **产品优先级最高的是前端美感与交互丝滑度；功能复杂性是第一阶段明确降级的项。**
- 体验基调（2026-08-28 修订）：面向大众审美的优雅与自然——克制、留白、呼吸感，不做刻意的悬念式表达。

### 1.3 目标用户

普通安卓用户（自装侧载分发起步）。所有文案以第一人称「我」的自述口吻书写，不出现任何「你和她 / 你们俩」式的两人称谓；架构上不做短期妥协，保留向应用商店上架演进的完整路径（见 §5.4）。对外的 README 与公开叙述保持含蓄（见 rules.md 叙事纪律）。

### 1.4 成功标准

1. 装上即用：APK 侧载后零注册零配置即可开始使用（默认值全部可用）。
2. 提醒尽力送达：完成一次性省电白名单引导后，标准方案下提醒稳定可达；同时允许整体关闭，不做强制保活黑科技。
3. 治愈感成立：打卡动画满帧流畅，"看着想多喝一杯"；界面与已确认的视觉稿一致。
4. 贴心感可感知：文案库里的话是写给自己的语气；问候语每次进入首页都有变化。

## 2. 视觉设计系统

### 2.1 四主题色板

四套主题共用完全相同的布局与插画，仅切换调色盘。所有主题统一叠加以下质感手法（见 2.2）。

| 元素 | A · 翡翠绿（默认/白天） | B · 草莓雾光（早晨） | C · 焦糖奶茶（傍晚） | D · 深夜墨青（深夜） |
|---|---|---|---|---|
| 背景渐变 | `#F3FBF7 → #E2F3EC → #D8EEE4` | `#FFFFFF → #FFF4F6 → #FFEAEE/#FFE5EB` | `#FFF8EA → #FFEED4 → #FFE2C0` | `#0B1412 → #0F1D1A → #122621` |
| 主色（进度环/强调） | `#0FA37A` | `#F9709A` | `#E8853F` | `#3ECFA5` |
| 进度环轨道 | `#BFEBDC` | `#FDE4EB` | `#F8DCBA` | `#1E3A33` |
| 环心数值文字 | `#0B7D5C` | `#EE6390` | `#BF671F` | `#7FE7C6` |
| 问候语文字 | `#14684E`（副 `#4F8A75`） | `#D0688A`（副 `#DB96AC`） | `#8F5626`（副 `#B89066`） | `#CDEFE2`（副 `#7FA99C`） |
| 按钮（线性渐变） | `#0E9F74 → #26BE8D` | `#F986A6 → #FFB3C8` | `#E07E36 → #FFAB57` | `#2FB98F → #4ADBB0` |
| 徽章底/字 | `#DCF1E8` / `#177A5C` | `rgba(255,233,240,.92)` / `#C9688A` | `#FFE9CC` / `#8F5626` | `#172B25` / `#A8D8C6` |
| 粒子色族 | `#10A87C #2BC493 #57D3AC #6ADBBC` | `#F9709A #F986A6 #FA9AB6 #FF9FBC #FFC2D4` 等 | `#E8853F #FFB761 #FFCF8E #FFE0AE` | `#3ECFA5 #5FDDBB #8AE8CE #2A6B58` |

深夜主题取向：保持品牌绿基因的「墨青底 + 薄荷强调」，不做纯黑——柔光晕与粒子在暗底上自然成为主角，系统栏随主题同步为深色并切换浅色图标。

字体：跟随系统圆体/无衬线（MiSans、HarmonyOS Sans、思源黑体等），不引入自带字体文件；大数字用中等偏粗字重保持圆润可爱。

### 2.2 统一质感手法（粒子系统）

1. **噪点颗粒层**：全屏叠加 4px 网格微点纹理（约 4–5% 不透明度、multiply 混合），去除大面积渐变的塑料感。
2. **柔光晕**：进度环背后一团模糊径向光晕（约 170px、主题主色低透明度），给粒子提供"过渡的场"。三主题均启用。
3. **分层漂浮粒子**：每屏十几个大小 2–7px 的圆形光点，分三层透明度（0.25–0.55 大颗+辉光 / 0.45–0.65 中颗微辉光 / 0.6–0.75 小颗无辉光），持续极缓上浮、顶部渐隐循环；个别位置点缀 ✦ 星芒。
4. 所有粒子颜色取自当前主题粒子色族。

### 2.3 时段自动换肤

| 时段 | 主题 |
|---|---|
| 06:00–10:59 | B 草莓雾光 |
| 11:00–17:59 | A 翡翠绿 |
| 18:00–21:59 | C 焦糖奶茶 |
| 22:00–05:59 | D 深夜墨青（静默时段，不发提醒） |

- 切换发生时界面做 0.5s 颜色平滑过渡（含背景渐变、环、按钮、粒子色族），禁止生硬跳变。
- 设置页可改为"固定某一主题"（默认为"跟随时间"）。

## 3. 信息架构与页面设计

底部导航三标签 + 开屏动画，共 4 个界面场景。

### 3.1 开屏动画

- 使用 AndroidX SplashScreen API 保持系统启动画面至首帧就绪，随后接续场内品牌动画，仅冷启动完整播放一次，全程约 1.2s：
  1. 柔和底色上，一颗主题色水滴从上方轻轻落下（spring 缓动）；
  2. 落水荡开两圈涟漪；
  3. 涟漪外圈生长变形为首页进度环的初始形态，画面淡入首页。
- 可跳过：任何点击立即进入首页；热启动不重播。

### 3.2 首页（治愈打卡页）

自上而下：

1. **时段问候语** + 日期副行（如"早安呀，今天也要甜甜的 ☀" / "8月27日 · 已完成 50%"）。问候语按早/午/晚分组内置，随主题同步切换。
2. **进度环（可点区域）**：环形水位表示今日 ml 进度；环心显示 `已喝 {ml}` 与小字"今日已喝"。整个环区接受点按打卡（视觉按压反馈缩放 0.97→1 回弹）。
3. **统计双徽章**：「今日 {N} 杯 ☀」「平均间隔 {h}h ⏱」——用户要求的直观反馈，数据来自 Room 聚合实时刷新。平均间隔 = 同一日内相邻两次记录的时间差平均值；当日不足两杯时显示「—」。
4. **健康小贴士行**（固定一行小字）：「📖 《中国居民膳食指南》建议成年人每日饮水 1500–1700ml」。默认目标量据此取 **1600ml**。
5. **「记一杯」大按钮**：胶囊形主按钮，主文案随主题变化（"喝一杯啦 ♡"/"干杯一下 💧"/"来一口温暖"）。
6. 全局：噪点颗粒 + 柔光晕 + 漂浮粒子背景。

### 3.3 统计页

给"坚持的痕迹"一个专属空间，三个模块纵向排列：

1. **徽章行**：今日杯数 · 平均间隔 · 连续达标天数（连续 ≥100% 目量计为达标；跨天未达标则清零重计）。
2. **本周柱状图**：近 7 天每日总量 vs 目标线，达标的柱子用主题主色高亮。
3. **今日时间线**：每杯一个小水滴节点 + 时间戳 + ml，空态文案温柔（"今天的第一杯还没出现哦"）。

### 3.4 我的（设置与心意管理）

分区列表，全部即时生效无需保存按钮：

- **目标**：每日目标量（默认 1600ml，步进 50）、一杯容量（默认 250ml，步进 50）
- **提醒**：总开关、清醒时段起止（默认 08:00–22:30）、提醒间隔（默认 90 分钟，可选 30–240）
- **外观**：主题模式 = 跟随时间（默认）/ 固定翡翠绿 / 固定草莓雾光 / 固定焦糖奶茶 / 固定深夜墨青
- **心意文案库**：进入文案编辑器，按早/午/晚分组管理句子（增删改）；提供"恢复默认文案"
- **引导**：重新打开省电白名单引导页

### 3.5 首次启动引导

仅在第一次启动时出现一页：欢迎语 + "去开启省电白名单，让提醒更可靠"主按钮 + "以后再说"次按钮。白名单跳转按机型 ROM 尽力匹配常见厂商设置页，失败兜底到系统应用详情页。

## 4. 核心功能规格

### 4.1 打卡（记录一杯）

- 触发途径一：点击「记一杯」按钮；途径二：点按进度环区域；途径三：通知上的「喝啦 💧」操作按钮。
- 每次记录 = 当前设置的一杯容量（默认 250ml）写入 `water_record` 表。
- 800ms 防抖：窗口内的连续多次触发只记一次。
- 记录发生的"归属日"以系统本地时间的自然日划分。

### 4.2 治愈反馈动画编排

打卡成功瞬间依次触发（重叠进行，总时长 ≤ 1.2s）：

1. 触发控件按压缩放回弹（~200ms，spring）
2. 进度环按新增比例推进（~600ms，ease-out 曲线）
3. 环心数字滚动到新值（~500ms）
4. 8–12 颗主题色粒子从触发点迸发、上浮渐隐（~900ms）
5. 随机夸夸短语在环下方淡入浮现（~1.4s 后淡出），取自对应时段文案组
6. **达成日目标的庆祝态**：满环微光呼吸 + 全屏粒子雨（~1.5s）+「今日份水灵达成 ✨」横幅浮现；当日后续打卡回到普通反馈

性能要求：粒子动画在 Compose Canvas 实现，随机种子记忆化避免重组抖动；中端真机上动画期间不得出现掉帧卡顿；App 内不需要粒子时可暂停绘制。

### 4.3 温柔提醒通知

- 独立通知渠道「温柔提醒」，重要性默认低（轻声、无横幅打扰，锁屏可见可关）。
- 在清醒时段内按间隔调度精确闹钟（AlarmManager.setExactAndAllowWhileIdle）；每次触发：
  - 标题：时段问候短句（"午后啦 ☀"）
  - 正文：从该时段文案组随机抽一句（近期用过的优先避开）
  - 操作：「喝啦 💧」= 记录一杯并展示一条极简确认（"记好啦 ♡"）
- 达成当日目标后当日剩余提醒自动取消。
- 兜底策略：Android 12+ 未授予 SCHEDULE_EXACT_ALARM 时自动降级 setWindow 非精确模式，不为权限打断她；设备重启后由开机广播 Receiver 重排当日剩余提醒。
- 关闭总开关即取消全部已排程闹钟；重新开启按当前时间重算下一个提醒点。

### 4.4 心意文案库

- 出厂内置 ~30 条（早/午/晚各一组），开发者可在交付前用设置里的编辑器整库替换成只属于两人的语言。
- 存储于 DataStore（JSON 序列化）；删除到最后一条时该时段回退到通用组兜底。
- 抽取消重：记录最近 5 条已用，优先从未用池抽取。

## 5. 技术架构

### 5.0 架构总原则：不为今天的天花板编码

本应用当前只有一个用户、一个功能面，但**可迭代、可优化、可扩展被定为一等需求**：模块边界从第一天就真实存在，未来加功能（新页面、桌面小组件，乃至上架商店）是"往骨架上长肉"，而不是推倒式重构。宁可初期多一点脚手架成本，换取长期每一轮迭代都在健康的结构上进行。

### 5.1 模块拓扑（Gradle 多模块）

```
:app                    # 壳工程：单 Activity、导航图、Hilt 装配、Splash 续场动画
:core:model             # 纯 Kotlin：领域模型与值对象（零 Android 依赖）
:core:common            # 纯 Kotlin：时钟源、Result 封装、时段判定等纯函数
:core:domain            # UseCase 层（仅依赖 :core:model / :core:common）
:core:data              # Repository 实现：Room、DataStore、文案库存储
:core:notification      # ReminderScheduler / ReminderReceiver / BootReceiver / NotifBuilder
:core:designsystem      # 三套 ThemeSpec 色板、粒子引擎、ProgressRing、通用组件
:feature:home           # 首页（治愈打卡）
:feature:stats          # 统计页
:feature:settings       # 我的 + 文案编辑器
:feature:onboarding     # 首启白名单引导
```

### 5.2 依赖规则（架构铁律，违者视同 bug）

1. `:core:*` 不知道任何 `:feature:*` 的存在。
2. `:feature:*` 之间禁止互相依赖；跨页跳转一律经由 `:app` 的导航表解决。
3. 依赖方向恒定：`ui → domain ← data`；`:core:domain` 不导入任何 Android/UI 类，保证纯 JVM 单测。
4. 数据访问只经 Repository 接口；Room/DataStore 的存在感不外泄到上层。

### 5.3 工程基线

- Kotlin DSL Gradle + Version Catalog（`libs.versions.toml`）统一依赖版本；Hilt 做装配；kotlinx-coroutines + StateFlow 是唯一异步语言。
- 单 Activity + Navigation Compose；MVVM 单向数据流：UI 事件 → ViewModel（StateFlow）→ UseCase → Repository → Room/DataStore → StateFlow 回流刷新。
- 数据库仅一张表 `water_record(id, amount_ml, drank_at_epoch_ms, day_key_local)`；今日合计/杯数/平均间隔/7 天柱状/连续达标天数均为聚合查询或内存推导。
- DataStore 键：goal_ml、cup_ml、window_start_min、window_end_min、interval_min、reminders_enabled、theme_mode、copy_library_json、recent_copy_ids、onboarding_done。
- minSdk 26（Android 8.0），targetSdk 采用实现期最新稳定版；不引入任何网络/Retrofit 类依赖。
- ktlint 随项目模板初始化，格式不合不入库。
- 时间处理统一以系统本地时区为准；检测到日期跳变（跨天/改时间）时按当前时间重建当日区间与统计缓存。

### 5.4 面向上架的演进预留

一期保持个人侧载分发，但以下事项已被结构预留，需要时只是补配置而非重构：

| 未来需求 | 现在的预留 |
|---|---|
| 上架 Google Play | release 签名配置、隐私政策披露（无网络权限天然友好）、通知权限与精确闹钟的合规说明话术 |
| 新页面 | 新增 `:feature:*` 模块即可，导航在 `:app` 注册 |
| 桌面小组件 | `:widget:*` 新模块直接复用 `:core:data` 与 `:core:designsystem` |
| 数据导出/备份 | `:core:data` 暴露接口即得，上层零改动 |
| 更多主题 | ThemeSpec 本就是数据驱动，加一套色板常量即可 |

## 6. 边角与错误处理

| 场景 | 处理 |
|---|---|
| 无网络/无账号 | 全功能离线可用，网络权限不声明 |
| 提醒权限缺失 | 通知权限被拒：保留应用内完整体验，设置页常驻温和的重开入口 |
| 精确闹钟被限制 | 自动降级 setWindow；引导页建议手动授"闹钟和提醒" |
| 国产 ROM 杀进程 | 白名单引导 + BootReceiver 重排双兜底；产品定位"尽力送达"，不再做激进保活 |
| 跨天边界 | 今日统计按自然日 0 点自动切分归零，界面无需手动刷新；23:00–06:00 为静默时段不发提醒 |
| 用户改系统时间 | 以系统时间为唯一事实源，异常跳跃按当前时间重建 |
| 数据增长 | 约 1k 行/年，不设清理策略 |

## 7. 测试策略

1. **单元测试（JUnit + 虚拟时钟）**：时段→主题判定边界（5:59/6:00/10:59/11:00…）；今日统计、平均间隔、连续达标天数计算；提醒next-fire-time 计算（含跨时段、开关切换、目标达成取消）。
2. **Room 内存库测试**：插入/聚合查询正确性、day_key 切分。
3. **Compose UI 测试**：打卡 → 徽章数字更新；防抖窗口合并；达标庆祝态触发一次且当日内不重复。
4. **人工验收清单（真机，开发者执行）**：开屏动画手感、三主题过渡丝滑度、打卡演出节奏、通知实机到达率（重点验一次白名单前后对比）。模拟器闹钟行为不可靠，提醒链路以真机为准。

## 8. 明确不做与二期备忘

一期不做：账号/云同步、丰富报表、饮品类型细分、多语言、强制保活。
二期彩蛋候选：桌面小组件（台面水滴）、虚拟小宠物养成、特殊纪念日彩蛋文案、iOS 版（若届时迁移 Flutter 另议）。

## 9. 变更记录（2026-08-28 使用者反馈修订）

1. **定位与视角**：去除「你和她 / 你们俩」式的两人框架；全部文案改为第一人称「我」的自述口吻，体验面向大众审美的优雅自然。
2. **问候语进文案库**：首页顶部时段问候语不再硬编码，改为从文案库对应时段组随机抽取；每次进入首页（新建导航栈条目）都换一句，去重池避免短期重复。默认语料由每时段 10 句扩至每时段 20 句。
3. **设置页步进修复**：目标量/杯容量步进改为 ViewModel 乐观更新（快速连点不丢步）；两行步进器由并排挤压改为上下整行排布。
4. **返回键退出**：修复底栏导航 `popUpTo` 指向已弹出 startDestination 导致的栈堆积——引导完成后切换页签不再往栈里压重复条目，系统返回键在首页可直接退出应用。
5. **粒子呼吸感**：圆点粒子 16→24 颗、星芒 2→3 枚，背景柔光晕增加约 8s 周期的轻呼吸（仅透明度，不重排版）。
6. **debug 构建包名后缀**：`applicationIdSuffix = ".debug"`，debug 与 release 可共存便于对照观察。

## 10. 变更记录（2026-08-29 显示效果优化迭代）

动效基调统一为**克制**：150–250ms、位移 ≤12dp、每屏只编排一次入场。

1. **深夜墨青主题（D）**：第四套色板（§2.1），跟随时段 22:00–05:59 自动启用，亦可固定选择；系统栏随主题动态同步（深色栏 + 浅色图标）。
