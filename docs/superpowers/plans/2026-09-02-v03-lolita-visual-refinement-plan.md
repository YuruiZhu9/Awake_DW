# Awake_DW v0.3 视觉优化实施计划：克制的 Lolita 喝水工具

- 日期：2026-09-02
- 状态：执行中
- 目标：在不增加产品复杂度的前提下，持续优化喝水记录与提醒的视觉质量。

## 0. 北极星与边界

Awake_DW 的产品核心只有喝水记录、喝水提醒、饮水事实统计和相关设置。Lolita 元素是设计语言，不是玩法、奖励或收藏机制。

本计划不加入：每日穿搭、衣橱、画廊、馆藏、解锁、钉选、连续达标奖励、亲密度、配饰成长、收藏册或任何新的养成循环。

## 1. 阶段状态

### 阶段 A · 范围收敛（已完成）

- [x] 新增 v0.3 产品范围与视觉方向 spec；
- [x] 移除今日之裙、画廊、穿搭、藏品解锁与相关 DataStore 契约；
- [x] 移除连续达标驱动的展示与奖励路径；
- [x] 首页回到喝水进度、记录入口和必要辅助信息；
- [x] 保留旧版本 DataStore 键但不再读取，避免升级时做破坏性迁移。

### 阶段 B · 设计系统收敛（已完成第一轮）

- [x] Material 组件接入 Awake 主题色，避免系统默认蓝色混入；
- [x] 统一衬线标题、控件形状和基础间距锚点；
- [x] 徽章改为半透明纸面 + 细蕾丝描边；
- [x] 新增无语义的 LolitaRule，作为页面结构分隔；
- [x] 快捷饮量改为轻量描边胶囊，降低色块密度；
- [x] 移除全屏庆祝粒子/横幅，保留核心进度反馈。

### 阶段 C · 首页主视觉（下一阶段）

目标：让使用者在 3 秒内读懂今日进度并完成一次记录。

- [ ] 重新审查问候、进度环、快捷饮量和主按钮的垂直节奏；
- [ ] 将主按钮与进度环建立更明确的视觉组；
- [ ] 评估漂浮粒子数量，避免与蝴蝶结、蕾丝和猫同时抢焦点；
- [ ] 将猫收敛为低存在感固定装饰/轻反馈，不占用核心操作空间；
- [ ] 增加首页四主题静态截图基线，逐屏比较文字、环和按钮的对比度。

### 阶段 D · 统计页与设置页统一

- [ ] 将统计图表、时间线和徽章纳入同一套纸面层级；
- [ ] 统计页只表达饮水事实，不出现坚持、奖励或成长语义；
- [ ] 设置页卡片保留蕾丝顶饰，但减少重复边框与过重阴影；
- [ ] 主题选择改为更像色卡的外观控件；
- [ ] 文案编辑器统一文本层级、焦点色和按钮触摸反馈。

### 阶段 E · 主题艺术资产

- [ ] 只制作固定主题背景、纸张纹理、蕾丝纹理和少量静态装饰；
- [ ] 资产命名使用 `art/theme_*`，不再使用 outfit/collection 语义；
- [ ] 每个主题先做一张代表性背景，确认可读性后再扩充；
- [ ] 加入采样解码、缓存、失败回退与 APK 体积约束；
- [ ] 资产不改变任何领域状态，不参与随机、解锁或奖励。

### 阶段 F · 动效与感官收口

- [ ] 记录按钮：按压、数字、进度环只形成一条清晰反馈链；
- [ ] 页面切换保持 150–250ms、位移不超过 12dp；
- [ ] 对系统减少动态设置提供温和降级；
- [ ] 声音仅作为可关闭的短反馈，尊重系统静音；
- [ ] 完成窄屏、大字体、深色主题、TalkBack 和中端设备验收。

## 2. 每阶段交付标准

每个阶段结束必须满足：

1. `./gradlew build` 全绿；
2. 有对应自动化测试或截图验收记录；
3. 不引入新的产品概念和持久化状态；
4. Lolita 元素仍然是结构装饰，而不是功能入口；
5. 产出可安装的 debug APK，必要时同步 release APK；
6. 代码、设计 spec、CHANGELOG 对当前行为保持一致。

## 3. 当前执行结论

截至 2026-09-03，阶段 A 与阶段 B 第一轮已经落地，当前仓库已回到“喝水工具 + Lolita 视觉”的正确方向。下一轮优先级是阶段 C：首页静态层级和主操作构图，而不是新增功能。

## 4. 外部素材与资料需求声明（2026-09-03）

本轮视觉迭代**不需要用户额外收集图片或资料**：布偶猫先用代码矢量重绘，页面质感使用现有主题色、纸面渐变、噪点、蕾丝和描金 token 完成验证。

如果后续要把布偶猫或背景替换为真实手绘/水彩位图，我会在开始产出前单独列出：所需图片尺寸、透明背景要求、风格参考、授权/来源信息和预计文件体积；在此之前继续推进无需外部素材的设计系统优化。
