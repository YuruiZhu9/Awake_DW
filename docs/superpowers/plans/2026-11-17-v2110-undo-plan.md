# v2.11.0 · 打卡纠错闭环（撤回上一杯）实施计划（2026-11-17）

> 状态：**代码侧完成（2026-11-17），待真机验收**；versionCode/versionName 未提升（仍为 53 / 2.9.0）。
> 上游：`docs/design/continuous-iteration-plan.md` §6 的 2.11.0；`docs/superpowers/checklists/v2.10.0-qa.md` 的「未做」项。
> 一句话：**刚按下的一杯，十秒内可以原地收回；撤回不再弹确认，历史记录仍走统计页的确认删除。**

## 1. 问题与依据

- 2.2.0 减法后，首页只剩「环 + 一件事」，撤回入口撤出首页；统计页的删除要「导航 → 找行 → 长按 → 确认」四步。
- 误触通常发生在按下后的几秒内：点错入口、选错快捷量、手滑。此刻的纠错应当和记录一样轻。
- NN/g《Confirmation Dialog》：确认弹窗只留给高风险、不可逆、低频的操作，「不要为日常动作使用确认弹窗」；同时应「尽最大努力提供 undo」。因此：
  - 打卡后的撤回**不弹确认**——它就是「收回刚刚那一下」；
  - 统计页对历史记录的删除仍保留 `AwakeConfirmDialog`（时间越久，撤销成本越高，确认越合理）。
- 既有约束：
  - 三条文字反馈通道（环心确认 / 环下达标横幅 / 猫语气泡）不得合并，也不新增第四条文字通道；
  - 不为视觉提示新增持久化键；不改业务、导航、权限；
  - 可点目标 ≥ 48dp；隐藏手势必须有可见说明——所以不做「长按撤回」这类无提示手势。

## 2. 落点决策：主按钮胶囊尾端

比较过三个候选：

| 方案 | 优点 | 否决/保留理由 |
| --- | --- | --- |
| 环下 8s 纸带 | 显眼、标准 | 与达标横幅同一物理分区；达标杯恰好最需要撤回，两条纸带会叠；且是第四条文字通道。否决。 |
| 统计页行内撤回 | 不动首页 | 已有带确认的删除；再加无确认撤回会与「历史记录需确认」的纪律冲突。不采用。 |
| 长按主按钮 + 提示 | 不占地 | 隐藏手势；10s 提示本身仍是一条新文案；长按与点按的语义差在触屏上不够稳。否决。 |
| **主按钮尾端动作（采纳）** | 与「记一杯」同源、零布局跳动、无新表面 | 10s 内尾端 `+250ml` 位置换成发丝分隔 +「撤回」，动作与记录发生在同一个控件上。 |

设计要点：

1. **不是新通道**：撤回是动作，不是反馈文案；它占用的是按钮里原本显示 `+{cupMl}ml` 的尾端槽位，不新增任何常驻/临时文字区。
2. **零布局跳动**：按钮仍为 56dp 高、整宽；尾端内容宽度变化只发生在右端，主文案「记一杯」不移动。
3. **窗口 10s**：足够读完环心一句引文再反悔；到期自动退回 `+{cupMl}ml`。再次成笔会重新开窗，撤回目标始终是「最新一杯」。
4. **撤回目标明确**：只删今日最后一笔（`DeleteWaterRecordUseCase.revertLatestToday()`）；回执走既有环心通道「已撤回 · {n}ml」。
5. **撤回即收场**：撤回成功后立刻收起撤回窗口、猫语气泡与达标横幅（那一杯已不存在，反馈不应滞留），并清掉旧防抖窗，允许马上补记正确的量。
6. **无持久化**：窗口只活在 ViewModel 内，旋转保留、进程死亡丢失——符合「不新增持久化键」。
7. **无障碍**：尾端动作是独立语义节点，`role = Button`，可见文案「撤回」，`contentDescription = "撤回上一杯，{n}ml"`，可点高度 ≥ 48dp；TalkBack 可聚焦、可激活。单指单击即可完成，满足 WCAG 2.2 SC 2.5.7。
8. **减少动态**：尾端切换使用 240ms Crossfade；减少动态下时长归零。
9. **声音**：撤回不播放任何音效；只给一次轻触觉（CLOCK_TICK），不把删除做成庆祝。

## 3. 状态与交互

`HomeUiState` 新增：

```kotlin
val undoAvailable: Boolean = false
val undoAmountMl: Int? = null
```

`HomeViewModel`：

- `UNDO_WINDOW_MS = 10_000L`；构造器增 `undoWindowMs`（测试可注入，生产缺省）。
- `logAndPraise` 在 `LogResult.Logged` 时调用 `openUndoWindow(record.amountMl)`：
  - `undoEpoch += 1` 并记下代次；
  - `undoAvailable = true`、`undoAmountMl = amount`；
  - `delay(undoWindowMs)` 后代次未变才收起。
- 防抖重复触发不成笔，**不**重开窗口。
- `undoLatestCup()`（尾端动作入口）先检查并同步收窗，再调用 `revertLatestCup()`；同一窗口只消费一次，快速双击不会删到再上一杯。
- `revertLatestCup()` 成功后：
  - `undoEpoch += 1`，`undoAvailable = false`、`undoAmountMl = null`；
  - `feedbackEpoch += 1`、`catEpoch += 1`，清 `celebrating` / `catLine`，猫心情按当前时段落回；
  - `lastAcceptedAt = now - logDebounceMs`，允许立即补记；
  - `showCenterNote("已撤回 · {n}ml")`。

`LogButton` 新增参数：

```kotlin
undoVisible: Boolean = false,
undoAmountMl: Int? = null,
onUndo: () -> Unit = {},
```

尾端：`undoVisible` 时显示「发丝分隔 + 撤回」；否则维持 `+{cupMl}ml`。

## 4. 非目标

- 不做撤回倒计时进度线（避免按钮内再长出一条装饰）。
- 不做「撤回后可重做（redo）」。
- 不把撤回做成滑动手势或长按手势。
- 不改统计页删除的确认流程。
- 不改通知动作「记一杯」——通知侧没有首页窗口，纠错仍走统计页。
