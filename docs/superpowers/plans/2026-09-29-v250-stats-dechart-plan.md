# 2.5.0 立项：统计页去图表化，回到记录（2026-09-29）

> 使用者反馈（2026-09-29，验收 2.2.0–2.4.0 后）：「统计的意义应该在于记录，而不是做成像柱状图的样子，
> 我个人觉得这个会增加人的焦虑。周统计和月统计足够，年统计完全没有必要。应用的定位是在健康、提醒。」
> versionCode 49。本轮是方向修正：统计页从「仪表盘/档案」退回「记录本」。

## 1. 设计决策

| 撤除 | 理由 |
| - | --- |
| **年度信纸**（2.3.0 引入） | 使用者明确否决：年统计完全没有必要 |
| **近七日柱状图**（`WeekBarsChart`） | 使用者点名「柱状图的样子增加焦虑」：柱体高低、目标虚线、刻度对齐都是比较与压力的语言 |
| **时段节律堆叠条**（`RhythmBars`） | 分布图是纯分析形态，与「记录」无关；撤除后全页不再有图表 |

| 保留/改造 | 形态 |
| - | --- |
| **近七日 → 周记录列表** | 七行发丝行（与今日时间线同一排版语言）：今天在最上，每行「今天／昨天／M月D日 + 毫升数」，行间只压发丝线；无柱、无目标线、无选中读数，量就摆在那，不比不催 |
| **本月热力（日历）保留** | 月历是「记录的样子」（像日历打卡），且使用者明确「月统计足够」；五档深浅降噪为三档（未饮/有记录/达标），数字仍逐格可读 |
| 今日 hero、事实格、今日时间线 | 原样（文本事实与发丝行本就是记录语言） |

- 热力三档（视觉基线修订 §18）：0 = 未饮（轨道色 30%）、1 = 有记录（主色 35%）、2 = 达标（主色 90%，字用 onPrimarySurface）；今天仍主色描边。
- 撤除后 `StatsMath` 的图表换算（柱高/目标线/列生长/列标签）与 `ArchiveMath` 的节律/信纸换算一并移除，不留死代码；`WaterRepository.recentRecords` 为只读接口保留不撤（避免接口与六处替手的无谓震荡）。
