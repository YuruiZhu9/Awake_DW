# 2.0.2 · 首页有效视口与英雄区几何修正计划（2026-09-28）

> 状态：**针对 2.0.1 实际布局反馈的立即修正**。这是空间关系修复，不是新风格探索。

## 1. 问题复盘（按 360dp 内容宽度测算）

- 首页水平边距各 28dp，内容宽度约 304dp。
- 2.0.1 英雄行右侧放 132dp 环并留 14dp 间隔后，左列只剩约 158dp。
- 左列又纵向堆了今日数值、目标文案与主按钮；行高由左列决定，显著高于 132dp 圆环，形成圆环下方空段，主按钮还被压窄。
- 既有首屏测试把 `HomeScreen` 单独放在 360×640 根视口，只检查按钮 `bottom <= root.bottom`；没有模拟 Scaffold 扣除系统栏/底导航后的可用高度，也没有断言按钮宽度和按钮相对英雄行的位置。这个验收不足以发现 2.0.1 的布局失衡。

## 2. 修正方案

- 英雄行只包含「今日饮水数值 + 132dp 紧凑仪表」，两者垂直居中；不再把主按钮放进左侧窄栏。
- 主按钮恢复全内容宽度，紧接英雄行（10dp 间距）；按钮仍显示当前一杯容量。
- 快捷饮量作为次级路径放在主按钮后方。
- 日期/问候、主题场景、猫咪常驻入口、事实摘要，以及环心/达标缎带/猫语三通道语义不改。
- SplashMorph 环心估算与英雄行间距同步；不改水量、目标、防抖或任何持久化行为。

## 3. 自动化验收（几何断言，不只验“存在”）

新增 `HomeScreenOverflowTest` 场景：360dp 宽、520dp 高的有效内容视口、fontScale 1.3。

- 主按钮完整处于首屏上方约 72% 区域内，给底部导航/系统手势区留下余量。
- 主按钮语义边界宽度 ≥ 根视口宽度的 82%，证明它是全宽主操作，不再是 158dp 窄栏按钮。
- 英雄行高度不超过 132dp 环直径 + 24dp，证明环没有被独立的按钮列拉长。
- 主按钮与英雄行间距 ≤ 18dp。
- 既有八主题截图复查同步重拍；原生截图只作诊断，真机仍是最终视觉闸门。
