## 3. 地基 A · 真机验收闭环（最高优先，先于一切视觉升级）

**为什么是第一位**：Z2。背景可见度四轮盲调、文案六轮返工的共同根因都是没有真机反馈——视觉问题呈「盲调多轮 → 使用者爆发 → 集中修一波」的脉冲。不先补这个闭环，任何视觉升级都会重演同一模式。

设计决策：
1. 每版本发布流程固定新增一环：出包后由使用者在真机走完该版 QA 清单并归档截图（adb 自动导出或手动截图均可）；未走完不宣称完整 Definition of Done（rules §八.5 的执行补强，不改规则本身）。
2. 0.6.0 前集中补验一次 0.4.0–0.5.1 累计欠账：将各版 QA 的未勾选项合并为单一补验清单（按「对比度 / 大字体与窄屏 / 三通道同屏 / 无障碍与减少动态 / 覆盖升级与签名」分组，一次真机会话完成）。
3. 若可建立 adb 连接，新增本地脚本一键导出关键页面截图到 `docs/superpowers/checklists/screenshots/`（本地归档，不新增网络与权限）。

验收条件：补验清单逐项有记录（通过 / 不通过 + 截图）；不通过项成为 0.6.0 的修复输入。
依赖：D1（验收方式与机型）。

## 5. 轨道一 · 内容策展化（0.6.0）

### 5.1 打卡引文：从古典诗文摘句改为散文 / 经典语录制

背景（Z4）：0.5.1 的原始诉求就是「瑞幸取餐小票式引文」，但语料选择了古典诗文摘句。执行下来违和的成因：① 2–15 字限制把诗句切成残句（「15 是给七言联句逗号留的位置」）；② 律诗对仗的文人气与纸面 lolita 的少女日常气是两种不兼容的「古雅」；③ 打卡瞬间的情绪是日常小确幸，生活化散文体（一眼读完、有共鸣）更匹配。

设计决策：
1. **形态与纪律不变**：仍是「正文 + 可选落款」，仍只取公有领域作品并逐条核对，原创句不伪造出处；三通道位置分离规则不动。
2. **语料来源更换**：从「古典诗文摘句为主」改为**散文句 / 经典语录为主**——中国古典散文与清言小品（《幽梦影》、题跋、书信一类短句）+ 公有领域西方作家短句（自译或古旧译本），保留少量原创句。具体配比按 D2 确认。
3. **长度纪律优先于排版让步**：语料控制在环心两行可容（实现时以最长样句实测折行定上限，基准约 14–18 字），超长句不入选——用选材纪律保住「不截断 + 零位移」共存，不靠加高预留或截断。
4. **第二人称**：语录池维持禁「你/您」，取材时逐句筛（公有领域短句中不含「你」的可选量充足，不必放宽全局规则）。
5. **落款上限**复核：按中译名放宽（如 2–8 字，容纳「陀思妥耶夫斯基」一类长名）。
6. **草案先行**：先出全量草案（早/昼/晚各 10 条 × 一批备选）供用户逐条圈选（D3），确认后才进代码。

需同步修改（实现 plan 详列）：`ShortCopies.praise*` 三池重写、`PraiseQuote` KDoc、`ShortCopiesTest` 长度/落款断言、`CopyLibraryRepositoryTest` 与 `RingNoteRenderTest` 例句、`HomeViewModelTest` 常量同步（若调 `PRAISE_HOLD_MS`）、visual-baseline §11/§12 对应句改写、CHANGELOG。

验收条件：全部引文公有领域且出处核对无误；最长句在八主题环心两行内可读（真机抽查挂在地基 A 补验）；语料测试全绿；猫语池与心意文案库不受影响。

### 5.2 心意文案库 108 句整体重写（D8 已确认随本轮执行）

108 句历史上经 0.4.1 润色、0.5.0 逐条重写两轮，仍是第一人称自述体；用户 2026-09-15 确认随引文库更换一并第三轮重写（见 §9.1）。重写只动默认值，不动编辑器、持久化键与整库可编辑规则；草案与引文草案同样走逐条圈选（D3）。

### 5.3 深夜青黛专属主图

依赖用户提供素材（S1）；未到位前维持现有回退，不阻塞 0.6.0 其余项。

## 6. 轨道二 · 视觉场景化（0.7.0 / 0.8.0）

### 6.1 前置：moodboard / 基线刷新（alpha13）

按 visual-baseline §7 与 AGENTS 约束，新素材与新艺术方向必须先更新 moodboard/spec。0.7.0 第一步：以用户新参考图（S3）+ 既有八主题为输入，产出 alpha13 基线增补，明确：

- **场景层级**定义：背景层 / 中景装饰层 / 近景前景层，及各层预算（尺寸、透明度、动幅）；
- **粒子预算**：按档位定颗数与密度（现有 QUIET 14 / STANDARD 24 扩到多少）；
- **动态强度分级**：QUIET / STANDARD 之上是否增设「沉浸」档及其触发场景；
- **AGSL 层使用范围**与 SDK < 33 回退策略。

**关键立场：场景化 ≠ 3D 化。** 借鉴的是「氛围场景 + 粒子环境 + 随时间演化」的层级概念，不是照搬全屏 WebGL；日用工具的可用性、OLED、减少动效与低端机预算优先。不引 3D 引擎（filament/unity）、不引网络资源、不做与纸面气质冲突的强对比特效。

### 6.2 0.7.0 · 分层视差与场景状态机（零新依赖，minSdk 26 不动）

- `LolitaBackdrop` 单层位图拆为 2–3 层（背景主图 / 中景装饰 / 近景蕾丝飘带），各层慢速漂移 + 视差；
- 粒子由 24 颗扩至 100–200 颗：复用 `ParticleMath` 纯函数架构，draw 相按层批量绘制，加正弦叠加流场；
- 新增 `SceneSpec` 场景状态机：主题 × 时段的连续氛围演化（渐变锚点、粒子色族、密度随时间插值），复用 `AnimatedAwakeTheme` 逐锚点插值模式；
- 动效 token 沉淀：时长 / 缓动 / 弹性统一收敛到 designsystem 常量。

依赖：试点主题分层素材（S2，先 1 个主题验证再铺开）；真机帧率数据（地基 A）。

### 6.3 0.8.0 · AGSL 氛围层（API 33+ 门控双路径）

`RuntimeShader` + `RenderEffect` 做全屏纸纤维流动 / 雾光 / 柔焦；SDK < 33 回退现有静态渐变 + 噪点；减少动态模式全部关停。不依赖新素材（着色器为代码），但必须有真机帧率与低端机降级数据后方可发布。

## 7. 轨道三 · 体验纵深（0.9.0，吸收 roadmap 0.5.x 两项候选）

- **统计周合计与达标天数**（roadmap 0.5.x 候选之二，属功能扩张，本轮立项确认）：统计页补周维度与达标天数，不动现有今日 / 近七日 / 时间线结构。
- **打卡仪式时刻**（需用户确认边界，D10）：当日首次达标从「环下缎带 2.5s」升级为一次全屏轻仪式——克制、可跳过、减少动态降级回缎带。这是「瞬间奖励感」的对应物；**只做每日一次的视觉仪式，不做积分、连击、收集**，是否触及 roadmap P2「不做奖励」的边界由用户明确确认。
- **夜间猫状态落差**（roadmap 0.5.x 候选之一）：22:00–06:00 安睡态与常驻「点击我试试~」入口的一致性方案随本轨出提案。
